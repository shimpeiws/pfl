# Security review — M6 Phase 4 (S5: pre-consent Git reads)

- Date: 2026-09-17
- Reviewer: `codex exec` (independent model), against the Phase 4 diff
- Trigger: changes in `src/discovery/project-identity.ts`, `src/discovery/consent.ts`
- Result: the main S5 paths were judged closed; one high finding (a symlinked
  `.git/config`), one consent-boundary finding, and two consequences were
  dispositioned

## Findings and disposition

| #   | Severity | Finding                                                                                                                                              | Disposition                                                                                                                                                                                                                                                                                                                                     |
| --- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | High     | `.git/config` was read with a plain `readFile`, so a symlinked `config` leaked an out-of-project remote into the id before consent                   | **Fixed.** `config`, `commondir`, and the `.git` file are read through `readTextFileGuarded` with the Git directory as the base, so a symlinked `config` is refused                                                                                                                                                                             |
| 2   | High     | `hasAnyUserConsent` crosses the runtime + scope consent boundary: a `claude-code:user` grant lets a read command follow a Codex checkout's `gitdir:` | **Accepted, recorded.** Consent states that `pfl` may read outside the project; the runtime scope selects harness files, not the runtime-independent Git metadata. A per-runtime gate needs the runtime before the project id is known, which is circular without M8's root index. Recorded as accepted risk A3; a unit test pins the behaviour |
| 3   | Consider | A pre-consent run from a subdirectory makes `project.root` the subdirectory, so repository-root project-scoped discovery can be missed               | **Accepted and documented** in ADR 0002 §2                                                                                                                                                                                                                                                                                                      |
| 4   | Consider | A snapshot written under a path-derived id while unconsented is not found once a grant switches reads to the remote-derived id                       | **Accepted and documented**; reclamation is M8's root index                                                                                                                                                                                                                                                                                     |

## Verification

- Falsifiability: reverting the `config` guard turns the symlinked-`.git/config`
  test red; reverting the gate turns the ancestor-search, `.git`-file, and
  out-of-project-remote tests red.
- Codex could not run the Vitest suite itself (read-only sandbox `EPERM` on
  `node_modules/.vite-temp`); the suite was run locally.
- Full gate green: `test` (293), `check`, `format`, `build`, `typecheck:test`,
  `knip`.
