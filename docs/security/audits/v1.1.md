## A3 — re-evaluation

A3's reopening condition was: "a read command gains a `--runtime` argument."

`--runtime` was added to all read commands (`inspect`, `report`, `list`, `show`,
`graph`, `diff`, `snapshots`) in the v1.1.0 delta (#180, #191). However, the
flag scopes only the "latest" run selection — it does **not** change the
`hasAnyUserConsent` gate that controls Git-metadata reads. The runtime-agnostic
consent check remains in `read.ts`, `snapshots.ts`, and `gc.ts`.

**Disposition:** A3 is **partially addressed** but not eliminated. The
`--runtime` flag makes the runtime known before project-id resolution, which
means a future change could use it to narrow the Git-metadata gate. For v1.1.0
the approximation remains as it was in v1.0 — the `--runtime` flag alone does
not change the trust boundary, so A3 stays accepted with the same reopening
condition. A follow-up should use `--runtime` to narrow `hasAnyUserConsent` to
the specified runtime's grants.

### T2 — Resolution semantics bump (1 → 2) (src/resolution/assemble.ts)

The derivation and relation rules changed. Stored resolved snapshots from v1.0
are incompatible with the new semantics. This is a MINOR-level change per
`docs/design/stability.md` — the schema version (`SNAPSHOT_SCHEMA_VERSION`)
is unchanged, but the semantics version feeds the resolved snapshot digest, so
old and new snapshots produce different ids.

No trust-boundary impact: the change is internal to the resolver.

### T3 — `--runtime` flag on read commands (#180, #191)

Scopes the "latest" run selection to a specific runtime. Does **not** change the
`hasAnyUserConsent` gate (see A3 re-evaluation above). No new read surface.

### T4 — Cross-runtime compat scopes (#165, #199)

Adapter-defined `-compat` scopes (e.g. `claude-compat`, `agents-compat`) are
surfaced in `report`, `list`, and `graph`. These are display/filter
annotations over already-collected consent-gated reads. No new read surface.

### T5 — Duplicate catalog name detection (#163)

Aggregation of `duplicate-element-name` diagnostics, bounded sample of 3 names
per bucket. Marketplace catalog clones suppressed (already treated as
never-loaded by resolution). Pure post-processing; no new reads.

### T6 — Nested checkout boundary pruning (#162, #173)

`lstat` on `<dir>/.git` for each child directory during project instruction
walks. Project-implicit read; bounded by `MAX_WALK_ENTRIES`. Conservative:
symlinked `.git` is also a boundary.

### T7 — Diagnostic message path readability (#179)

`redactDiagnostic` scoped high-entropy catch-all to non-path tokens. Strengthens
redaction for embedded paths while keeping diagnostic messages useful. No new
read surface.

### T8 — Project dir dot encoding (#177)

`encodeProjectDir` now maps `.` to `-`, matching Claude Code's real layout.
`redact/output.ts` deduplicates the encoding logic. Strengthens redaction for
dotted home directories.
